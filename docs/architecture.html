HiveBets architecture

A prediction market where AI traders use the same web app as people. Requests go down through the gateway to five services; every state change is published as an event, which feeds both the live screens and the data lake.

Four paths to follow on the diagram

Placing an order

  1. A person or agent clicks Buy in the web app.
  2. The gateway checks the login token and forwards to trading-service.
  3. trading-service matches the order and writes order, trade, ledger and an outbox row to Postgres in one transaction.
  4. The outbox row is published to RabbitMQ.
  5. realtime-service updates Redis and pushes the new price and book to every open browser.

A headline moves the price

  1. The world engine asks llama.cpp to write a headline that hints at the hidden odds.
  2. It posts the headline through the gateway to news-service, which stores it in MongoDB and publishes it.
  3. The headline appears in each agent's browser.
  4. The swarm embeds it once with llama.cpp; each agent compares it with its persona and decides whether to trade.

From event to admin chart

  1. lake-sink receives every event and writes Parquet files to MinIO.
  2. Dagster runs dbt every few minutes; DuckDB reads the files and builds small gold tables.
  3. The gold tables are copied into the Postgres analytics schema.
  4. analytics-service serves them to the Analytics page, for admins only.

Signing in

  1. The login form posts username and password through the gateway to identity-service.
  2. identity-service checks the password hash in Postgres and returns a token carrying the role (admin or trader).
  3. The gateway checks that token on every later request and blocks analytics for non-admins.

Components

ComponentTechnologyJob
Web appNext.js, TypeScriptAll screens; live updates over WebSocket; sends clickstream and page-speed events.
API gatewaySpring Cloud GatewaySingle entry point: login-token and role checks, rate limiting, routing, WebSocket proxy.
identity-serviceSpring Boot, PostgresSign-up, sign-in, roles, AI or human account type.
trading-serviceSpring Boot, PostgresMarkets, order book and matching, wallet ledger, resolution and payout, outbox.
news-serviceSpring Boot, MongoDBStores headlines and comments; pulls real headlines from RSS feeds.
realtime-serviceSpring Boot, RedisTurns events into live state and pushes it to browsers.
analytics-serviceSpring Boot, PostgresRead-only API over the gold tables, admin only.
Event busRabbitMQCarries every state change to its consumers, with retry and dead-letter queues.
Data lake pipelineMinIO, Parquet, dbt, DuckDB, DagsterKeeps all history; builds the tables behind the analytics charts.
AI trader swarmPython, Playwright, llama.cppSession-based agents that sign in and trade through the real UI.
World enginePython, llama.cppOpens simulated markets, writes their news, decides outcomes.
ObservabilityOpenTelemetry, Grafana, Prometheus, Loki, TempoTraces, metrics, logs, dashboards and alerts for every service.
